# Data

This directory contains the input datasets, prepared data products, and selected derived files used by the reproducibility workflow for:

> **Reconstructing East Asian Temperatures from 1368 to 1911 Using Historical Documents, Climate Models, and Data Assimilation**

The main computational workflow is executed from the repository root using:

```bash
REPRODUCTION_MODE=full \
Rscript --vanilla run_all.R
```

Most intermediate products generated by the workflow are written under:

```text
Output/Intermediate/
```

The `Data/` directory primarily contains the datasets required to start the analysis and selected derived files used by downstream scripts.

## 1. REACHES Documentary Temperature and Precipitation Data

The main REACHES source file is:

```text
Data/temperature index value.v1.xlsx
```

The analysis scripts extract the documentary temperature level, calendar year, longitude, and latitude from this workbook.

This file is used by several parts of the analysis, including:

- Figure 2;
- calibration of the interval-censored covariance model;
- interval-censored kriging;
- Figure 5;
- Figure S2;
- the documentary-coverage and population analysis; and
- the held-out interval-compatibility validation.

The documentary temperature index is an ordinal, dimensionless quantity. Missing values are represented as `NA` after import into R.

### Documentary precipitation data

The accompanying annual and seasonal REACHES precipitation records are available in:

```text
Data/precipitation index value.xlsx
```

The workbook includes the annual worksheet `全年降水分級` and seasonal worksheets. The documentary precipitation analyses described below use **only the annual worksheet**, to avoid mixing annual and seasonal entries.

The two source workbooks contain documentary event identifiers, historical years, and georeferenced locations. The analysis uses year, longitude, and latitude to join the precipitation and temperature records at the **site-year level**. This association does **not** require the two records to come from the same text or the same season. Text and event identifiers are retained where available for interpretation and source auditing.

The following scripts use the precipitation workbook:

- `Code/Analysis/precip_temperature_joint_distribution.R`: estimates the empirical distribution of recorded temperature indices by preliminary rain, snow, and hail event-code categories, conditional on a recorded temperature index at the same site-year. The category rules are provisional and should be checked against the REACHES event-code dictionary. The analysis does not fill missing temperatures. It writes tables and a plot under `Output/Intermediate/Precipitation/`.
- `Code/Analysis/prepare_precipitation_augmented_reaches.R`: creates an optional site-year temperature input with a working value of zero for site-years that have an annual precipitation record but no recorded temperature index. Existing temperature indices are preserved exactly. Precipitation entries include dry-weather and other precipitation-related documentary events: this working rule treats a precipitation record as evidence of documentary availability, not necessarily evidence that precipitation occurred.

The augmented input and its source-audit tables are written to:

```text
Output/Intermediate/REACHES/temperature_site_year_augmented.csv
Output/Intermediate/REACHES/temperature_inferred_zero_audit.csv
Output/Intermediate/REACHES/temperature_augmented_metadata.csv
Output/Intermediate/REACHES/temperature_augmented_by_block.csv
Output/Intermediate/REACHES/temperature_augmented_by_year.csv
```

The `source_type` and `is_inferred_zero` fields distinguish observed temperature categories from inferred zero values. The original Excel workbooks are never overwritten. An inferred zero is an explicit modeling assumption rather than a documented normal-temperature event.

### Augmentation diagnostics

The optional script `Code/Analysis/diagnose_precipitation_augmentation.R` validates the augmented site-year file against the original annual temperature workbook and precipitation records. It does not change the inferred-zero rule or write to either source workbook. In particular, **all annual precipitation-related records, including no-rain and drought reports, are eligible** to support the documentary-availability assumption.

The script summarizes the original and augmented temperature-index counts for the full 1368–1911 period and five historical blocks; counts and coverage for years newly represented after augmentation; two-degree geographic density cells; supporting precipitation-record multiplicity; and event-code categories. Rain, no rain, drought, snow, snow absence/prayer, and hail are preliminary **non-exclusive** event descriptors, not a partition of the data. The snow-absence/prayer code group does not imply an explicit observation of no snow in every record. No temperature index is derived from these categories.

After running the data-preparation script, the diagnostics can be generated independently:

```bash
Rscript --vanilla Code/Analysis/prepare_precipitation_augmented_reaches.R
Rscript --vanilla Code/Analysis/diagnose_precipitation_augmentation.R
```

Outputs are saved under:

```text
Output/Intermediate/Precipitation/AugmentationDiagnostics/
```

These include block/year CSV summaries, the newly informative years, event-category counts and combinations, source-record counts, two-degree spatial count grids, and corresponding plots. The diagnostics do not run calibration, kriging, or assimilation.


From the repository root, run the descriptive analysis with:

```bash
Rscript --vanilla Code/Analysis/precip_temperature_joint_distribution.R
```

To enable the augmented temperature input for the full reproduction workflow:

```bash
REACHES_TEMPERATURE_INPUT=augmented REPRODUCTION_MODE=full Rscript --vanilla run_all.R
```

The default workflow uses the original temperature workbook. When `REACHES_TEMPERATURE_INPUT=augmented`, the master workflow generates the site-year dataset before covariance calibration and kriging. To compare both analyses, retain separate copies of the generated outputs because both modes use the same `Output/` paths. The precipitation workbook is used by default from `Data/`; the optional `REACHES_PRECIPITATION_FILE` environment variable can override its path.

### WorldClim Climatological Bias-Correction Data

The prepared WorldClim bias-correction data are stored in:

```text
Data/WorldClim/worldclim_offsets_all_269.csv
```

This file contains location-specific additive temperature corrections for the CESM Last Millennium Ensemble (LME).

The corrections are calculated by comparing WorldClim v2.1 mean temperatures for 1970–2000 with the corresponding climatology from 13 CESM-LME ensemble members.

The file contains 269 locations:

- 266 native LME grid locations;
- Beijing, Shanghai, and Hong Kong validation stations.

The main variables include:

- `site`: location identifier;
- `longitude`, `latitude`: spatial coordinates;
- `type`: grid location or validation station;
- `WorldClim_1970_2000_C`: WorldClim reference climatology;
- `LME_1970_2000_C`: corresponding LME climatology;
- `d_C`: additive correction in degrees Celsius;
- `worldclim_available`: availability of a direct WorldClim value;
- `correction_method`: method used to determine the correction.

Locations without valid WorldClim data have missing correction values and are not automatically corrected using inverse-distance weighting (IDW).

The prepared CSV is used by:

```text
Code/DataPreparation/prepare_worldclim_bias_correction.R
```

The original WorldClim GeoTIFF and LME NetCDF preparation procedure is documented in:

```text
Data/Get_data/GetWorldClim.R
Data/Get_data/README.md
```

The default reproducibility workflow uses the prepared CSV and does not require the original large climate archives.


## 3. GHCN Instrumental Temperature Data

The GHCN data used for instrumental validation are stored in:

```text
Data/GHCNv4.xlsx
```

This file is used by:

```text
Code/Figure10.R
```

The city-specific REACHES, LME, assimilation, and GHCN analyses use the following nominal GHCN station coordinates:

| City | Longitude | Latitude |
|---|---:|---:|
| Beijing | 116.283 | 39.933 |
| Shanghai | 121.433 | 31.167 |
| Hong Kong | 114.167 | 22.333 |

Longitude and latitude are expressed in decimal degrees east and north, respectively.

The REACHES predictions are kriged directly at these coordinates. The LME temperature fields are spatially interpolated to the same nominal coordinates.

## 8. Units and Missing-Value Conventions

Unless otherwise specified:

| Quantity | Unit or convention |
|---|---|
| Calendar year | Common Era year |
| Longitude | Decimal degrees east |
| Latitude | Decimal degrees north |
| REACHES documentary level | Dimensionless ordinal index |
| LME temperature input | Kelvin where applicable |
| Processed LME temperature | Degrees Celsius |
| Calibrated REACHES temperature | Degrees Celsius |
| Assimilated temperature | Degrees Celsius |
| Variance or MSPE | Squared units |
| Standard deviation | Original units |
| Missing values | `NA` |

Prediction variance and prediction standard deviation are treated as distinct quantities throughout the kriging, quantile-mapping, and assimilation workflows.
